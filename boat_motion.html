A steady reference that preserves each stroke’s movement

The updated analysis uses a slowly changing neutral hull plane from gravity directions averaged over complete neighbouring strokes. Its default window is 20 seconds. Pitch and set retain their movement within the stroke while slower shifts in the reference are removed.

The phone axes are not automatically the boat axes. Use a known signed bow direction and correct phone-to-pin offsets when available. Otherwise, automatic direction inference uses the rowing pattern and remains an estimate.

This is a rowing-relative reference, not an independent hull-level calibration. Slow real trim changes and slow mounting/reference drift cannot be distinguished without a known hull datum. The local reference removes them together. Earth-up remains separate for gravity subtraction; instantaneous drive acceleration is not treated as the neutral level.

Under the server’s boat settings, Local gravity is the current default and Whole session permits a legacy comparison. The reference window can be set from 5–120 seconds. These are processing settings: re-analyse to change them. Reference support does not bridge sensor gaps.

Updated iOS and server processing use the same neutral-reference method. Live iOS estimates can only use observations already recorded; final app refinement and server analysis can use more neighbouring data. Their results can therefore differ around boundaries, gaps and later corrections.

Compare size and timing together

Speed swing and set range are Core metrics. Pitch range, heave excursion and mean set are Advanced choices. Ranges describe the difference between high and low values within a stroke; smaller movement does not automatically mean faster rowing.

Compare at similar rate and effort. Look at when acceleration changes relative to catch and release and whether a pattern repeats over several strokes. Fused ground speed adds faster detail when inputs support it; it does not measure speed through water.

How much does speed vary through a cycle?

The new Core checks use fused GPS + IMU speed from catch to the next catch, including recovery. The reference is a boat travelling steadily at the same time-weighted mean speed.

  • Distance check · cm: the maximum minus minimum accumulated position relative to that reference boat.
  • Speed check · m/s: the maximum minus minimum speed relative to the same mean.
  • Energy-loss check (V²) · %: the excess integral of squared speed, divided by the steady-speed V² integral, multiplied by 100.

At constant speed the energy-loss check is 0%. Variation raises it under this V² model. It is a comparison index, not measured resistance energy or a direct estimate of extra work by the rower. Ground-speed data does not supply speed through water.

Checks require a complete, supported fused-speed cycle with a positive mean. They are calculated before curve thinning; missing or gapped input shows no value. Group, piece and workout summaries show the arithmetic mean of valid member-stroke values for all three checks. The summary labels begin with Average. No check is summed or duration-weighted; the energy result averages the individual stroke percentages.

Speed swing and Surge excursion remain separate IMU-relative measures; do not substitute them for these fused checks.

Course and turning

Drive and recovery turn are Advanced choices, split at the measured feather/release event. Select native hull turn or course-relative turn through the shared turning control.

Straight course uses the piece endpoint line. Curved course follows a fitted gradual path. Signed course offset, RMS offset and estimated extra ground distance depend on that reference and sufficient supported GPS travel.

Steering, a bend in the course, wind and unequal oar action can create similar turns. Boat motion alone does not identify their cause.

Waterline and the inner wetted edge

When the recording supplies an explicit physical waterline height relative to the pin, the updated server can use that reference and its context. A manual physical reference takes precedence over a measured one. Without an explicit height, the default animation estimates a waterline that puts one-third of the blade’s vertical height under water at the Y-catch reference, averaged across supported catches.

The app’s new optional squared-float step saves an oar reference and carries it in the upload. That saved reference is distinct from the physical waterline-height input. Until the report explicitly identifies it as applied, do not assume the server has used the float measurement to set blade depth or waterline.

Adjust Waterline offset to explore the model. Enable Show blade slip trail to see the existing outer trace and a dashed inner trace. The inner trace follows the submerged hatchet edge nearest the handle; when the shaft enters the water, it follows the shaft centreline to the surface intersection. The current marker is labelled Inner blade or Wet shaft.

The trail changes with depth, feathering, set, pitch, heave, waterline and visual exaggeration, and breaks across dry or unsupported intervals. It illustrates geometric contact, not measured blade immersion, a fluid wake or water speed. The water texture is a ground-speed cue, not a current measurement.

Experimental slip

Slip compares modelled oar motion with available boat-speed information. It requires synchronized recordings, geometry, an angle-placement reference and an assumed current when interpreting motion relative to water. The report still uses a simplified rigid-oar model.

Average drive slip is signed longitudinal slip over sufficiently supported intervals: positive means rearward, and negative values are retained. Missing sections are not filled with zero. Signed displacement can decrease; cumulative rearward travel in Diagnostics cannot.

Slip in metres per second differs from catch miss, which is angular travel before sustained load. Use slip as an experimental comparison under its stated assumptions, not a calibrated measure of blade connection or boat speed through water.

Before drawing a conclusion

  • The phone remained rigidly attached to the hull.
  • The forward direction, clock alignment and neutral-reference setting are credible.
  • The selected strokes have the phone, oar and GPS coverage needed for the chosen signal.
  • Explicit oar lengths, rig geometry and phone-to-pin offsets match the setup.
  • The report identifies which waterline and oar-angle reference it actually uses.
