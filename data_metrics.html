A shorter set of useful choices

Begin with rate, power, Work per stroke, Loaded arc, catch miss, finish wash and Rhythm. Add GPS pace, heart rate and boat response when recorded.

The current report uses Core, Advanced and Diagnostics detail levels. Advanced includes Core; Diagnostics adds processing checks. The tables below describe the retained choices. Missing data stays unavailable; a dash is not zero.

Loaded arc was previously labelled Stroke length. Work per stroke is drive work. Rhythm is the recovery-to-drive ratio. These naming changes do not change the underlying calculations.

Core oar and effort metrics

MetricUnitsMeaning
PowerWWork per stroke divided by the full stroke cycle, including recovery.
Work per strokeJPositive calibrated moment integrated through forward sweep in radians. Missing load samples are identified in diagnostics; do not mistake missing input for measured zero load.
Peak loadN·m or NPeak moment about the pin, or estimated perpendicular handle force. Choose units; force needs a valid lever arm.
Loaded arc°Sweep from sustained load engagement to unloading, with the end capped at the feather threshold if load persists.
Catch miss°Sweep before sustained load engagement. The default bend threshold is 0.1°, with a 0.25-second confirmation window.
Finish wash°Sweep from unloading to the feather threshold, normally 15° from the drive roll baseline. It can be negative if feathering precedes unloading; a feather-capped loaded arc gives zero finish wash.
Total sweep arc°Forward sweep from the catch reference to maximum sweep. Catch miss, Loaded arc, finish wash and release travel describe its parts.
Mid work%Position where half the drive work is accumulated, as a percentage of Loaded arc. Below 50% is more front-loaded.
RhythmratioRecovery duration divided by drive duration, using sweep reversal points.
Drive timesTime from catch to the drive-ending sweep reversal.

Diagnostics and measurements kept out of the chooser

Diagnostics includes raw forward acceleration, baseline shaft inclination, raw bend checks, source/coverage and missing-load indicators, and cumulative rearward slip travel where supplied. These help assess a recording or processing result.

Optional individual-sensor GZ appears only as preset group/piece averages. Individual GZ traces are not stored in the HTML, so they cannot be displayed or averaged into a new browser group. Use the normal oar-speed curve for stroke comparisons.

The following are no longer ordinary table/plot choices: pin height and travel, tilt-only pin components, relative forward displacement, vertical velocity, redundant boat ranges and rates, duplicate depth summaries, per-distance turn variants, drive acceleration, mean drive/recovery speed, max-bend position, max work per degree, heart-rate calories, and power speed/distance. Internal values needed by calculations, calibration and replay are retained. Selecting Diagnostics does not restore every internal field.

Calibration, smoothing and stored detail

The Moment/Bend Factor converts bend into moment. It changes load and effort-derived values without changing GPS travel, stroke angles, timing or rotation speeds. The current app displays MBF in N·m/°. The supplied server field Saved bend factor (FBF, J/°²) uses the older coefficient: FBF = MBF × π/180, or MBF = FBF × 180/π. A normal iOS upload carries the recorded factor; use this conversion only when entering a value manually into a field with the corresponding label and units.

Metric smoothing and curve storage are separate. Longer reports may reduce points in individual display traces; numerical metrics and original server averages are computed before that reduction. A browser-created group uses the stored traces and can therefore have approximate curves.

Keep the source workout to rerun an analysis or inspect full diagnostics. Available choices follow the version that generated the HTML and the inputs it received.
