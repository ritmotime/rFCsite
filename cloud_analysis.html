After upload: one analysis workflow

  1. Upload the complete workout. Select its ZIP or the supported files from the same session. Keep original timestamps, phone data and saved settings together. Check the detected boat/session ID.
  2. Choose workout settings. When prompted, select Settings from this session, a Saved set identified by date, Uploaded edits for this workout if present, or Default settings.
  3. Review the differences and press Use these settings. Changing the dropdown alone does not apply the choice. The populated analysis fields remain editable. With no competing history or edits, the session settings or defaults may load directly.
  4. Check side, calibration and boat setup. Review alignment warnings, recorded oar details and any changes you intend for this analysis.
  5. Press Analyze workout. Open the completed report. Use Re-analyze when changing processing settings; the settings you use are remembered for your login.

Phone motion, GPS and heart rate appear only when the upload contains usable data. Keep your original ZIP and download the completed HTML report.

Recorded oar settings stay with the workout

New supported iOS recordings capture each oar’s dimensions and calibration at recording time, including when a bend factor or stiffness value was entered manually. In upload and Re-analyze, open Recorded oar settings to review:

  • Oar identity, recording slot and physical rowing side.
  • Total length, inboard/outboard, pin and sensor positions, and any saved calibration dimensions.
  • Saved calibration, manual inputs and the factor actually applied during recording.

These recorded values are separate from editable analysis inputs and reusable settings. Changing an analysis factor does not rewrite them. Two-oar recordings retain separate snapshots; do not substitute one oar’s dimensions for the other. Missing values in older recordings remain unknown.

A valid recorded single-oar inboard can supply the handle-force lever arm when no explicit analysis value is set. Retaining a dimension does not mean every geometry-based calculation uses it automatically: review the corresponding analysis field.

Alignment and calibration are different

Mounting alignment puts the sensor axes into a common oar frame. Stiffness calibration converts bend into load. A correct factor cannot repair an invalid mounting alignment.

For app-processed iOS DAT recordings, the server respects the alignment already applied by the app. For raw Android TXT recordings, it uses a suitable uploaded alignment or the validated saved alignment for the same mounting setup. If neither is usable, the warning identifies raw sensor axes; inspect that warning before interpreting the result.

For iOS, recorded calibration takes priority unless you request an explicit analysis override; a normal upload carries that value for you. The current app displays Moment/Bend Factor (MBF) in N·m/°. The supplied server form labels its older coefficient field Saved bend factor (FBF, J/°²). If you manually transfer a displayed MBF into that FBF field, use FBF = MBF × π/180. In the other direction, MBF = FBF × 180/π. Convert only when the destination label and units call for it; the two numbers are not interchangeable.

New recordings retain more sensor information

Current iOS recording packages can include full-rate oar acceleration beside the gyro recording, and separately timed fresh magnetometer packets when magnetic recording is enabled and the sensors reply. Preserve the complete export so those inputs remain available for later processing.

The server accepts and retains these inputs. Their presence does not mean the server already recomputes magnetic catch angles. An older workout cannot gain acceleration or magnetic samples that were never recorded.

The optional squared-float reference is saved with the oar and included in current app exports. It is distinct from an explicitly supplied physical waterline height. Do not assume it has been applied to server depth or waterline calculations unless the report identifies that reference.

Pieces, groups and your own comparisons

Pieces are continuous stretches of qualifying rowing. Automatic groups collect similar strokes, potentially from different parts of the workout. Review the rate, handle-speed and power grouping settings before analysis.

Afterward, zoom Session Overview and make a named group from its visible strokes. Compare that selection in the summaries, Boat & Oar averaged curves, individual strokes and GPS track.

Open curves and check the full stroke

The updated report starts at All available so every stored public metric and curve can be chosen. Use Averaged curves or Individual curves to open the averaged or single-stroke view directly. Core, Advanced and Diagnostics remain available as shorter chooser filters.

The new Core Distance check, Speed check and Energy-loss check (V²) use a complete catch-to-catch GPS + IMU fused-speed profile, including recovery. They compare it with steady travel at its time-weighted mean speed. The percentage uses the excess V² integral relative to the steady baseline; it is a modelled speed-variation check.

Re-analyse the original workout with the updated server to calculate these checks. Complete supported phone and GPS data is needed. Missing samples and gaps are not replaced with zero, and a display curve with reduced detail is not used to manufacture full-resolution results.

Keep a report you can open again

Download the HTML report and retain your original workout ZIP. Re-analysis can reuse uploaded files while the server retains them; your own copy lets you upload again later.

Open the HTML in a browser with JavaScript enabled. Embedded data and plots can be viewed locally; background maps require internet access. Download selected CSVs, plot images or a standalone animation to keep your comparisons.

These guides describe the supplied app and server updates. Your installed app and running analysis server determine which features are available. Updating this website does not update either one, and existing HTML reports keep their original data and controls.

Check the analysis result

Open the generated report and click Show stroke checks in Session Overview or All Strokes for Distance check, Speed check and Energy-loss check (V²). They require complete catch-to-catch GPS + phone-motion coverage. Oar-only uploads can still provide oar metrics, but cannot supply fused-speed checks.

Piece, group and workout checks are labelled Average and use the arithmetic mean of valid member-stroke values, with no sums or duration weighting. Missing cycles are excluded rather than treated as zero. Use All available to inspect every public metric or curve stored in that report.

Re-analyse an older workout with the updated server to generate the new calculations. Updating the website or opening an old downloaded HTML does not recompute its metrics. Definitions, units and required inputs →

For a saved iOS workout, open Workout Metrics → Recalculate boat checks. The app uses that workout’s original native phone/GPS files and saved settings, updates the supported checks, and preserves the other stroke metrics. A missing source file or unsupported cycle stays unavailable. Open All Stroke Metrics in the same section to inspect individual values.
